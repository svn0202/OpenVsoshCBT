# Предварительная генерация вариантов

Панель **Тесты → Генерация вариантов** создаёт варианты до одновременного
старта участников и тем самым переносит тяжёлую выборку вопросов из пикового
момента в подготовительный этап.

Генерация выполняется пакетами не более 25 участников. Экран показывает общее
число назначенных участников, число подготовленных вариантов, уже начавших
работу и ожидающих генерации. Повторяйте создание партии, пока счётчик
ожидающих не станет равен нулю.

Каждая попытка создаётся штатным серверным генератором в транзакции. В каталоге
участника подготовленная, но ещё не открытая попытка показывается как доступная
для начала. Статус «Продолжить» и отсчёт времени включаются только при первом
реальном открытии теста. В браузер
участника не выгружается автономный пакет или ключи правильных ответов.

## Инвалидация

Для неоткрытого варианта хранится SHA-256-отпечаток всех входов генерации:

- настроек теста и случайной выборки;
- наборов тем;
- вопросов и ответов;
- групп теста;
- групп конкретного участника.

Перед новой партией и при первом входе участника отпечаток вычисляется снова.
Устаревший неоткрытый вариант удаляется каскадно и создаётся заново. Попытка,
которую участник уже открыл, не изменяется.

## Обновление существующей установки

После полного дампа БД примените:

- MySQL/MariaDB — `install/upgrade/mysql/openvsosh_pregeneration.sql`;
- PostgreSQL — `install/upgrade/postgresql/openvsosh_pregeneration.sql`;
- Oracle — `install/upgrade/oracle/openvsosh_pregeneration.sql`.

Перед олимпиадой выполните генерацию на тестовой копии с плановым числом
участников и измерьте длительность партий и нагрузку БД. Не включайте
искусственную задержку старта без отдельного нагрузочного обоснования.

## Воспроизводимый нагрузочный профиль

Интеграционный тест `PregenerationLoadHttpTest` создаёт две одинаковые когорты,
авторизует каждого участника и одновременно открывает тест:

- первая когорта создаёт варианты непосредственно в момент старта;
- для второй администратор сначала создаёт варианты штатными партиями;
- после запуска проверяются HTTP-ответы, число попыток, снятие признака
  предварительной генерации, p50, p95 и общее время когорты.

Профиль отключён в обычном наборе, потому что число участников должно задаваться
явно:

```bash
TMF_PREGEN_LOAD_PARTICIPANTS=25 \
TMF_PREGEN_LOAD_MAX_P95_MS=10000 \
vendor/bin/phpunit --no-coverage test/integration/PregenerationLoadHttpTest.php
```

Параметры подключения к отдельной БД и `TCEXAM_APP_URL` задаются так же, как
для остальных интеграционных тестов. Отчёт сохраняется в
`target/report/pregeneration-load.json`. Запускайте профиль только на одноразовой
копии: он временно создаёт пользователей, вопросы, тест и попытки.

Контрольный локальный прогон 27 июля 2026 года на PostgreSQL 16.6, PHP 8.5.8 и
однопроцессном тестовом HTTP-сервере прошёл для 25 одновременных запросов.
Для варианта из 20 вопросов с четырьмя ответами p95 составил 6215 мс при
генерации на старте и 5788 мс после предварительной генерации; подготовка партии
заняла 923 мс. Улучшение p95 — 6,87 %. Однопроцессный сервер намеренно даёт
консервативные абсолютные задержки и не подтверждает вместимость боевого
Apache/PHP-FPM. Плановое число участников конкретной площадки нужно принять
отдельно на её стенде.

По этому сравнению искусственная случайная задержка старта не вводится: она
ухудшит наблюдаемое время участника, но не снимет работу генератора с пикового
момента. Для управления пиком используйте предварительную генерацию и измерения
на целевой инфраструктуре.
