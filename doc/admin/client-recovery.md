# Совместимость клиентов и восстановление ответа

`tmf_testend.php` — страница восстановления для старых клиентов. Она не завершает
попытку, не повторяет POST и не требует сессии, чтобы показать отправленный черновик.
Публикуется только явный переход в актуальный интерфейс; текущая авторизация
проверяется на целевой странице. Вывод POST ограничен полями ответа и экранирован.

Старые `es5.js`, `timer.min.js`, `plugins.ajax-json-cache-api-loadall.js` через Apache
отдают `legacy-client-recovery.js`: уведомление, показ черновика и явный переход.
Это выход из устаревшего интерфейса, а не запуск прежней логики завершения/сохранения.
Исторические OpenSans и IcoMoon сохранены для совместимости старых страниц.

Новый интерфейс сохраняет черновик в `sessionStorage` исходной вкладки отдельно для
попытки и вопроса. Токен и cookie туда не записываются. После перезагрузки
восстановление выполняется только кнопкой, сохраняет исходную версию и не обходит
конфликт более новой записи. Черновик предлагается в течение суток и удаляется после
подтверждённого сохранения неизменённого ответа. При запрете storage остаются форма
и кнопка скачивания черновика; прикреплённые файлы в черновик не входят.

После `session_required`/`csrf_failed` повторный вход выполняется в другой вкладке.
Нажатие сохранения в исходной вкладке сначала проверяет доступ и обновляет CSRF.
Смена учётной записи не обходит проверку принадлежности попытки. Сам вход не запускает
автоматическое сохранение или переход. Восстановить уже закрытый/утраченный браузерный
черновик этими изменениями невозможно.

Apple URL с типовыми размерами и `precomposed` обслуживаются исходным PNG через
AliasMatch, включая корень, `/public/` и `/public/code/`. Это алиасы одного оригинала,
а не обещание разных физических размеров. Изображение масштабируется устройством.

## Служебные файлы

- `robots.txt` запрещает обход: это не замена авторизации.
- `traffic-advice` отключает предварительные запросы `prefetch-proxy`, MIME
  `application/trafficadvice+json`; обычные действия участника не блокируются.
- `assetlinks.json` по умолчанию `[]`: делегирование Android-приложениям отсутствует.
  Для связи нужны подтверждённые package name и SHA-256 сертификата подписи. Отдавать
  JSON200 без перенаправления.
- `ads.txt` содержит установленную спецификацией строку отсутствия авторизованных
  рекламных систем. Реальных продавцов добавлять только по данным владельца сайта.
- `security.txt` создаётся для конкретной установки после указания публичного контакта.
  Не подменять контакт владельца адресом разработчика upstream. Команда:
  `python3 tools/render_security_txt.py --contact mailto:security@example.org --expires 2027-03-01T00:00:00Z --output /private/staging/.well-known/security.txt`.
  Адрес в примере не является рабочим контактом; перед выкладкой нужен реальный.
  Обновлять до истечения Expires, а не бесконечно продлевать его при каждом запросе.

Спецификации: [RFC9116](https://www.rfc-editor.org/rfc/rfc9116.html),
[Digital Asset Links](https://developers.google.com/digital-asset-links/v1/create-statement),
[traffic-advice](https://github.com/buettner/private-prefetch-proxy/blob/main/traffic-advice.md),
[ads.txt1.1](https://iabtechlab.com/wp-content/uploads/2022/04/Ads.txt-1.1.pdf).

Проверки без Docker: `python3 test/client_recovery_regression.py`,
`python3 test/answer_access_regression.py`, `python3 test/release_assets_regression.py`.
На кандидате дополнительно проверить Apache aliases/MIME, GET/POST старой страницы,
внешний вход и сохранение синтетического ответа с подтверждением в БД.
