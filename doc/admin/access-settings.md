# Настройка получения доступа

OpenVsoshCBT позволяет управлять публичными способами получения учётной
записи без изменения PHP-конфигурации.

## Где находится настройка

Откройте в панели администратора раздел **Настройки**. В блоке
**Доступ к платформе** доступны:

- **Отключить форму регистрации** — скрывает ссылку регистрации и запрещает
  прямое открытие формы;
- **Отключить форму сброса пароля** — скрывает ссылку сброса и запрещает
  прямое открытие формы;
- **Помощь по получению доступа** — выводит на странице входа инструкцию,
  контакты координатора или порядок выдачи логина.

Текст инструкции хранится в базе данных и ограничен 5000 символами. Он
выводится как обычный текст: HTML-код не исполняется, переносы строк
сохраняются. Не размещайте в инструкции пароли, токены и другие секреты.

Если инструкция не заполнена, на странице входа остаётся стандартная
локализованная подсказка.

## Значения по умолчанию

Пока настройки ещё не сохранены в БД, система использует значения
`K_USRREG_ENABLED` и `K_PASSWORD_RESET` из рабочего конфигурационного файла.
Это сохраняет поведение существующей установки при обновлении.

Отключение регистрации не аннулирует уже отправленные ссылки подтверждения:
пользователь по-прежнему может закончить ранее начатую регистрацию.

## Обновление существующей базы

Перед первым использованием примените файл для своей СУБД:

- MySQL/MariaDB — `install/upgrade/mysql/openvsosh_access_settings.sql`;
- PostgreSQL — `install/upgrade/postgresql/openvsosh_access_settings.sql`;
- Oracle — `install/upgrade/oracle/openvsosh_access_settings.sql`.

Приложение также пытается создать таблицу автоматически, чтобы старый
экземпляр не перестал открываться сразу после обновления кода. Для рабочего
сервера всё равно рекомендуется явная миграция: учётной записи приложения не
нужно выдавать постоянное право на изменение схемы БД.

Настройки записываются в таблицу `tce_openvsosh_settings`. Если при установке
использован другой префикс таблиц, замените `tce_` в SQL-файле на свой.
