# Listening-тесты

Для вопроса с аудиофайлом можно ограничить число запусков через поле
**Лимит запусков аудио** в редакторе вопроса. Ноль означает отсутствие
ограничения. При импорте Word используйте метку `[[AUDIO_PLAYS=2]]`.

Счётчик хранится для конкретного участника, теста, вопроса и аудиофайла в
браузере. Переход к другому вопросу и перезагрузка страницы его не сбрасывают.
Пауза и продолжение с текущей позиции не считаются новым запуском; повтор с
начала считается.

Это организационное ограничение интерфейса, а не средство криптографической
защиты файла. Перед экзаменом проверьте воспроизведение на фактических
браузерах и устройствах, а также предусмотрите резервные наушники.

## Приёмка

Минимальный браузерный сценарий находится в
`test/fixtures/browser-acceptance.html`. На размере 390 × 844 проверьте:

1. начальное сообщение сообщает о двух доступных запусках;
2. после первого запуска и reload остаётся один запуск;
3. после второго появляется сообщение об исчерпанном лимите и
   `aria-disabled="true"`;
4. третий запуск не меняет состояние;
5. страница не получает горизонтальную прокрутку.

Автоматизированный запуск требует Python Playwright и установленных движков:

```bash
playwright install chromium firefox webkit
python3 test/browser_acceptance.py
```

27–28 июля 2026 года этот сценарий пройден в мобильных профилях Chromium,
Firefox 146 и WebKit 26, установленном Safari 26.5.2 и Safari в iPhone 16e
Simulator: счётчик сохранился после reload, второй запуск исчерпал лимит,
третий не снял блокировку, а аудиоконтрол получил отключённое состояние.
Отдельный iPad (A16) Simulator подтвердил планшетную RTL-компоновку без
горизонтального переполнения. На арабской странице начальное, остаточное и
исчерпанное состояния показаны на арабском, а не на языке, зашитом в JavaScript.
Эти проверки не воспроизводят аудиокодек или аппаратный вывод на целевых
Android WebView и физических устройствах.
