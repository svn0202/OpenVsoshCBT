# Резервное копирование и восстановление

Панель **Система → Резервное копирование** создаёт архив базы данных и
восстанавливает выбранный архив из закрытого каталога `admin/backup/`.

Поддерживаются:

- MySQL/MariaDB через `mysqldump` и `mysql`;
- PostgreSQL через `pg_dump` и `pg_restore`.

Официальный Docker-образ уже содержит обе пары клиентов. На shared hosting
проверьте их наличие у провайдера: одного PHP-доступа к базе недостаточно.

## Гарантии механизма

- команды запускаются без shell-интерпретации;
- пароль передаётся дочерней утилите через переменную окружения и не попадает
  в строку процесса;
- код завершения и непустой архив проверяются до сообщения об успехе;
- частичный архив удаляется при ошибке;
- готовый архив публикуется атомарно и не перезаписывает файл с той же меткой
  времени;
- имя и реальный путь выбранного файла проверяются, символические ссылки
  отклоняются;
- перед каждым восстановлением автоматически создаётся дополнительный
  проверенный архив текущего состояния;
- временный распакованный дамп удаляется и не остаётся в веб-каталоге.

## Проверка восстановления

Не считайте наличие файла достаточной проверкой. На тестовом сервере:

1. создайте резервную копию;
2. запишите контрольное значение;
3. измените его после создания архива;
4. восстановите архив;
5. убедитесь, что вернулось исходное значение и приложение авторизуется;
6. сохраните дату, размер архива, версии сервера и клиентов БД.

Интеграционный набор проекта выполняет этот сценарий на отдельной одноразовой
базе: создаёт архив, изменяет контрольную строку, восстанавливает архив и
проверяет исходное значение. Проверка конкретного shared hosting всё равно
нужна, потому что провайдер может запрещать запуск внешних программ.
